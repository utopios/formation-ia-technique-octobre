# TP 5 — Mini-projet : un assistant à outils avec orchestration et streaming

> Module : 5 — API des modèles génératifs, automatisation et orchestration
> Durée estimée : 2h00
> Difficulté : 4 / 5
> Type : Travaux pratiques guidés — version Java


## Mise en situation

Un LLM seul ne sait pas calculer de façon fiable, ni consulter une base, ni appeler une API. Le **function calling** (ou *tool use*) change la donne : on déclare des outils (méthodes Java), le modèle **décide** lesquels appeler et avec quels arguments, on **exécute** l'outil, on **renvoie** le résultat au modèle, et on **boucle** jusqu'à la réponse finale. C'est le cœur d'un agent.

Dans ce mini-projet, vous construisez cet assistant à outils sur le même patron que le programme de référence du module 5 (`FunctionCallingEtStreaming`), mais avec des outils volontairement DIFFÉRENTS de la démo : une **consultation de stock produit** et une **conversion de devises** (mockées). Même mécanique, nouveau terrain : un **protocole JSON explicite** (un modèle 1b n'a pas de tool calling natif fiable : le modèle répond `{"outil": ..., "arguments": {...}}` et c'est votre code qui exécute — exactement la même logique que les blocs `tool_use`/`tool_result` des API cloud), une **boucle d'orchestration** robuste, une **gestion des tours** (budget d'itérations), et enfin le **streaming** de la réponse token par token. Tout tourne en local via Ollama, en Java standard (`java.net.http` + Jackson).

## Objectifs

- Déclarer des outils (protocole JSON dans le message système) et implémenter une boucle d'orchestration : le modèle appelle, on exécute, on renvoie, on boucle jusqu'à la réponse finale.
- Rendre la boucle robuste : extraction tolérante du JSON émis par le modèle, coercition des types d'arguments, et budget de tours pour éviter les boucles infinies.
- Recevoir une réponse en streaming (token par token) et comprendre la gestion des tokens et du budget.

## Architecture cible

```
   question utilisateur
        |
        v
   messages = [system (protocole JSON des outils), user]
        |
        v
  +------------------------------- BOUCLE (maxTours) --------------------------------+
  | POST /api/chat (temperature 0, stream:false)                                     |
  |        |                                                                         |
  |   extraireAppelOutil(contenu) == null ? --- oui ---> reponse finale -> SORTIE    |
  |        | non ({"outil": ..., "arguments": {...}})                                |
  |        v                                                                         |
  |   executerOutil(appel)  (coercition de types, erreur -> {"erreur": ...})         |
  |        v                                                                         |
  |   messages += {assistant: decision} puis {user: "RESULTAT DE L'OUTIL ..."}       |
  +-----------------------------------------------------------------------------------+
        |
        v
   STREAMING : POST /api/chat stream:true -> un chunk JSON par ligne (ofLines)

   Outils locaux : stock_produit(reference) | convertir_devise(montant_eur,devise_cible) [mockes]
```

## Étapes

### Étape 1 — Déclarer les outils et leur protocole (25 min)

Objectif : écrire les méthodes Java réelles et le message système qui les déclare au modèle.

1. Créez `src/main/java/fr/utopios/formation/module05/MonTp05.java` avec les outils :

   ```java
   package fr.utopios.formation.module05;

   import com.fasterxml.jackson.databind.JsonNode;
   import com.fasterxml.jackson.databind.ObjectMapper;
   import com.fasterxml.jackson.databind.node.ArrayNode;
   import com.fasterxml.jackson.databind.node.ObjectNode;
   import fr.utopios.formation.commun.Llm;

   import java.net.URI;
   import java.net.http.HttpClient;
   import java.net.http.HttpRequest;
   import java.net.http.HttpResponse;
   import java.time.Duration;
   import java.util.Map;

   public class MonTp05 {

       private static final ObjectMapper MAPPER = new ObjectMapper();
       private static final HttpClient HTTP = HttpClient.newHttpClient();

       static Map<String, Object> stockProduit(String reference) {
           return switch (reference.toUpperCase()) {
               case "REF-101" -> Map.of("quantite", 42, "entrepot", "Lille");
               case "REF-205" -> Map.of("quantite", 0, "entrepot", "Nantes",
                       "note", "rupture - reapprovisionnement le 15");
               case "REF-330" -> Map.of("quantite", 7, "entrepot", "Lyon");
               default -> throw new IllegalArgumentException("reference inconnue : " + reference);
           };
       }

       static double convertirDevise(double montantEur, String deviseCible) {
           return switch (deviseCible.toUpperCase()) {
               case "USD" -> montantEur * 1.08;
               case "GBP" -> montantEur * 0.85;
               case "JPY" -> montantEur * 161.0;
               default -> throw new IllegalArgumentException("devise inconnue : " + deviseCible);
           };
       }

       // Le PROTOCOLE JSON explicite : la déclaration d'outils, dans le system.
       private static final String SYSTEME = """
               Tu es un assistant qui peut utiliser des outils.

               Outils disponibles :
               1. stock_produit — donne le stock d'une reference produit.
                  Appel : {"outil": "stock_produit", "arguments": {"reference": "REF-XXX"}}
               2. convertir_devise — convertit un montant en euros vers une autre devise.
                  Appel : {"outil": "convertir_devise", "arguments": {"montant_eur": nombre, "devise_cible": "USD|GBP|JPY"}}

               Regles STRICTES :
               - Si la question porte sur un stock ou une conversion de devise, reponds
                 UNIQUEMENT avec l'objet JSON de l'appel d'outil, sans aucun autre texte.
               - Quand un message "RESULTAT DE L'OUTIL" arrive, n'appelle PLUS d'outil :
                 donne la reponse finale en francais, en citant le resultat tel quel.
               """;

       public static void main(String[] args) throws Exception {
           // Étape 1 : tester le DÉTERMINISTE d'abord, hors LLM.
           System.out.println(stockProduit("REF-101"));   // {entrepot=Lille, quantite=42}
           System.out.println(convertirDevise(250, "USD")); // 270.0
           // ... les étapes 2 et 3 viendront ici ...
       }
   }
   ```

2. Lancez : `mvn -q compile exec:java -Dexec.mainClass="fr.utopios.formation.module05.MonTp05"`.

Point de contrôle : les deux outils renvoient les bons résultats appelés directement (42 unités à Lille, et 270.0). Le message système décrit fidèlement leurs paramètres (types, valeurs autorisées) : c'est votre `input_schema` maison.

### Étape 2 — La boucle d'orchestration robuste (50 min)

Objectif : laisser le modèle appeler les outils et boucler jusqu'à la réponse finale, en gérant les fragilités d'un petit modèle.

1. Ajoutez l'extraction tolérante de l'appel d'outil (le 1b émet parfois un JSON imparfait) :

   ```java
   import java.util.regex.Matcher;
   import java.util.regex.Pattern;

   private static final Pattern OBJET_JSON = Pattern.compile("\\{.*\\}", Pattern.DOTALL);

   /** Premier objet JSON parsable du texte (tolère une accolade en trop). */
   static JsonNode premierObjetJson(String texte) {
       Matcher m = OBJET_JSON.matcher(texte);
       if (!m.find()) return null;
       String candidat = m.group();
       for (int essai = 0; essai < 3; essai++) {
           try {
               return MAPPER.readTree(candidat);
           } catch (Exception e) {
               if (!candidat.endsWith("}")) return null;
               candidat = candidat.substring(0, candidat.length() - 1).strip();
           }
       }
       return null;
   }

   /** Extrait un appel d'outil, ou null si c'est une réponse finale. */
   static ObjectNode extraireAppelOutil(String texte) {
       JsonNode obj = premierObjetJson(texte);
       // Repli : le 1b oublie parfois l'accolade ouvrante ("outil": ... }).
       // -> si pas d'outil trouvé mais que le texte contient "outil",
       //    retenter avec "{" + texte à partir de "outil".

       ...
   }
   ```

2. Ajoutez l'exécution avec coercition de types (jamais d'exception brute) :

   ```java
   static String executerOutil(ObjectNode appel) {
       String nom = appel.get("outil").asText();
       JsonNode args = appel.get("arguments");
       try {
           if ("convertir_devise".equals(nom)) {
               // asDouble() convertit aussi "250" (string) -> 250.0 : coercition.
               return String.valueOf(convertirDevise(args.path("montant_eur").asDouble(),
                       args.path("devise_cible").asText()));
           }
           return MAPPER.writeValueAsString(stockProduit(args.path("reference").asText()));
       } catch (Exception e) {
           return "{\"erreur\": \"" + e.getMessage() + "\"}";   // renvoyé au modèle
       }
   }
   ```

3. Écrivez la boucle d'orchestration avec budget de tours. Squelette :

   ```java
   static String assistant(String question, int maxTours) throws Exception {
       ArrayNode messages = MAPPER.createArrayNode();
       // 1. empiler {role:"system", content:SYSTEME} puis {role:"user", content:question}
       for (int tour = 1; tour <= maxTours; tour++) {
           // 2. POST /api/chat sur Llm.BASE_URL : model=Llm.modeleChat(),
           //    stream:false, options.temperature=0.0, messages
           // 3. contenu = message.content de la réponse
           // 4. appel = extraireAppelOutil(contenu)
           //    - null -> return contenu (réponse finale)
           //    - sinon : resultat = executerOutil(appel), afficher la trace,
           //      empiler {assistant: contenu} PUIS
           //      {user: "RESULTAT DE L'OUTIL <nom> : <resultat>\nDonne maintenant
           //       la réponse finale en français en citant précisément les valeurs
           //       de ce résultat."}
       }
       return "(limite de tours atteinte sans réponse finale)";
   }
   ```

4. Dans `main`, posez les deux questions du programme de référence :

   ```java
   for (String q : java.util.List.of(
           "Utilise l'outil stock_produit pour me donner le stock de la référence REF-101.",
           "Utilise l'outil convertir_devise pour convertir 250 euros en dollars (USD).")) {
       System.out.println("REPONSE : " + assistant(q, 5));
   }
   ```

5. Point clé d'orchestration : on **ré-empile le message assistant** (qui contient l'appel d'outil) *avant* d'ajouter le message user avec le résultat. Si vous inversez l'ordre, le modèle perd le lien entre l'appel et le résultat.

Point de contrôle : trace attendue — le modèle émet `{"outil":"stock_produit",...}`, votre code affiche `-> résultat : {"entrepot":"Lille","quantite":42}`, et la réponse finale cite 42 unités à Lille. Même chose pour la devise (270.0). La boucle se termine toujours (réponse finale ou limite de tours). Température 0 : la trace est reproductible. Observez la reformulation du modèle sur la devise : il peut écrire « 270,00 € » au lieu de dollars — l'outil est fiable, la REFORMULATION doit être vérifiée (unités !) : c'est un argument de plus pour le human-in-the-loop.

### Étape 3 — Streaming et gestion des tokens (30 min)

Objectif : recevoir la réponse au fil de l'eau et raisonner sur le budget de tokens.

1. Ajoutez une démo de streaming :

   ```java
   import java.util.stream.Stream;

   static void demoStreaming() throws Exception {
       System.out.print("\nRéponse en flux : ");
       ObjectNode corps = MAPPER.createObjectNode();
       corps.put("model", Llm.modeleChat());
       corps.put("stream", true);                     // <- LE paramètre du streaming
       corps.putArray("messages").addObject().put("role", "user")
               .put("content", "Énumère 3 avantages du streaming, très brièvement.");
       HttpRequest requete = HttpRequest.newBuilder()
               .uri(URI.create(Llm.BASE_URL + "/api/chat"))
               .header("Content-Type", "application/json")
               .timeout(Duration.ofMinutes(5))
               .POST(HttpRequest.BodyPublishers.ofString(MAPPER.writeValueAsString(corps)))
               .build();
       int morceaux = 0;
       // En streaming, Ollama envoie UN OBJET JSON PAR LIGNE (NDJSON).
       HttpResponse<Stream<String>> reponse =
               HTTP.send(requete, HttpResponse.BodyHandlers.ofLines());
       for (String ligne : (Iterable<String>) reponse.body()::iterator) {
           if (ligne.isBlank()) continue;
           System.out.print(MAPPER.readTree(ligne).path("message").path("content").asText());
           System.out.flush();                        // affichage immédiat
           morceaux++;
       }
       System.out.println("\n[streaming terminé : " + morceaux + " morceaux reçus]");
   }
   ```

2. Exécutez. La réponse s'affiche progressivement (une centaine de morceaux pour quelques phrases). En production, le streaming améliore la latence perçue et, côté API cloud, il est **obligatoire** au-delà d'environ 16K tokens de sortie.

3. Gestion des tokens : chaque tour d'orchestration ré-envoie tout l'historique (messages + résultats d'outils), donc l'entrée grossit à chaque tour. Pour budgéter : limitez `maxTours`, tronquez l'historique ancien si besoin, et lisez `prompt_eval_count` / `eval_count` sur les réponses non streamées (la couche `Llm` les affiche à chaque appel : `[llm] modele=... tokens_prompt=... tokens_reponse=...`).

Point de contrôle : la réponse arrive en plusieurs morceaux affichés progressivement, avec le compteur final. Vous savez expliquer pourquoi l'entrée grossit à chaque tour agentique et comment borner ce coût.

## Dépannage courant

<details>
<summary>Le modèle n'appelle jamais d'outil (répond directement, parfois faux)</summary>

Cause : un petit modèle 1b ne suit pas toujours le protocole, surtout si la question est vague.
Solution : température 0 (reproductibilité), et formulez la question pour inciter à l'outil (« utilise l'outil stock_produit... »). Vérifiez que le message système est bien le PREMIER message.

</details>

<details>
<summary>L'appel d'outil est détecté comme réponse finale (JSON malformé)</summary>

Cause : le 1b émet parfois un JSON sans accolade ouvrante ou avec une accolade en trop.
Solution : c'est exactement le rôle du repli dans `extraireAppelOutil` (restaurer l'accolade, retenter) et de la boucle de `premierObjetJson` (retirer une accolade en trop). Comparez avec la solution.

</details>

<details>
<summary>Erreur à l'exécution d'un outil (`IllegalArgumentException`, valeurs à 0)</summary>

Cause : le modèle a produit des arguments avec des types incorrects (nombres en chaîne) ou une opération inconnue.
Solution : `asDouble()` de Jackson gère la coercition des nombres ; l'exception d'un outil doit être transformée en `{"erreur": ...}` renvoyé au modèle, jamais propagée.

</details>

<details>
<summary>La boucle ne se termine pas / atteint la limite de tours</summary>

Cause : le modèle ré-appelle un outil en boucle sans converger.
Solution : `maxTours` borne le nombre d'itérations et garantit une sortie. La consigne « n'appelle PLUS d'outil » après le résultat, dans le système, est là pour ça.

</details>

<details>
<summary>Le streaming n'affiche rien progressivement</summary>

Cause : la sortie est tamponnée.
Solution : conservez `System.out.flush()` après chaque fragment, et utilisez `BodyHandlers.ofLines()` (pas `ofString()`, qui attend la fin de la réponse). Ne redirigez pas la sortie vers un fichier.

</details>
